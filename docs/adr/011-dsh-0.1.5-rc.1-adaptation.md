# ADR-011: 适配 DSH 0.1.5-rc.1（client-runtime 移除、settings namespace 字符串化、依赖策略对齐官方）

## Status

Accepted

## Date

2026-09-10

## Context

DSH 官方发布 v0.1.5-rc.1，插件原依赖矩阵（`@deepseek-ai/*` `0.1.0-rc.6` + cordis `4.0.1`）出现多处破坏性变化。以官方发布产物为本源逐包核实（全局安装的 `@deepseek-ai/dsh@0.1.5-rc.1` 与 npm registry），与本插件直接相关的契约变化：

1. **`@deepseek-ai/dsh-client-runtime` 包移除**。client 端 `ClientContext` 类型来源消失；其承载的 `slots` 服务改由 `@deepseek-ai/dsh-client-ui-renderer` 声明（`Context.slots: SlotRegistry`，`inject`/`register(options, component)` 形状不变）。
2. **`@deepseek-ai/dsh-client-ui-slots` 不再独立随应用分发**（打包进 ui-renderer），但仍发布 npm 且**仍在运行时模块表内**；SlotMap 声明合并的类型契约仍以它为家（`settings.section` 由 `dsh-client-ui-settings` 声明、`shell.overlay` 由 `dsh-client-ui-layout` 声明，形状均未变）。
3. **`dsh-settings` 的 `settingsNamespace()` 品牌函数移除**：namespace 改为普通小写连字符字符串，合法性由泛型参数（`SettingsNamespaceInput<Namespace>`）在编译期校验；`register/get/update/replace/mutate`、`SettingsPathOp`、`ctx.settings.*` 签名不变。
4. **客户端 `IWorkspaces.openPath` 移除**（`dsh-api-workspace-controller`）：「自定义人设 ↗」等三处直达打开失去宿主能力。
5. **运行时模块表（seed table）变化**（实测 dist boot 载荷）：`react`、`react/jsx-runtime`、`react-dom(/client)`、`cordis`、`dsh-client-store`、`dsh-client-ui-slots`、`dsh-client-ui-primitives`、`dsh-client-ui-dockkit`；`dsh-client-web-react`、`dsh-client-schema-form` 出表，`dsh-client-runtime` 随包消失。
6. **官方插件依赖模式**（以官方 `dsh-client-ui-*` 插件包为范本）：peerDependencies 仅 `@deepseek-ai/cordis: ^4.0.2`（+ react），DSH 各包按类型引用放 devDependencies；`dsh.client` manifest 的 `inject` 字段官方语义为「informational package-name dependencies, not Cordis service injection」。

未变部分（逐一核对，零改动）：`dsh-host-webserver` 的 `WebRoute`（kind/path/handler）与 `webServer.register`；`dsh-agent` 的 `agent/status`、`agent/error`、`agent/turn-stopping` 事件载荷；`dsh-user-approval` 的 `approval/request` waterfall 签名；设置面板导航图标仍按 section id 硬编码（未知 id 齿轮），爪印 DOM 替换方案继续有效。

## Decision

1. **ClientContext 类型改从 cordis 导入**：`import type { Context as ClientContext } from '@deepseek-ai/cordis'`——与官方 client 插件（`dsh-client-ui-open-in-app` 等）完全一致的写法；纯类型导入构建期擦除，不产生模块表请求。
2. **settings namespace 直接传字符串**：`const NS = SETTINGS_NAMESPACE`（`'live2d-pet'` 字面量类型天然满足编译期校验），删除 `settingsNamespace` 引用。
3. **依赖矩阵对齐官方模式**：
   - peerDependencies 收敛为 `@deepseek-ai/cordis ^4.0.2` + `react`/`react-dom`；
   - `dsh-agent`、`dsh-host-webserver`、`dsh-settings`、`dsh-user-approval` 全部转 devDependencies（`^0.1.5-rc.1`，源码对其引用全为纯类型）；
   - 移除已不存在的 `dsh-client-runtime` 与不再需要独立依赖的 `dsh-client-ui-slots`；
   - `dsh.client` manifest 移除语义不符的 `"inject": ["slots"]`（服务注入由 client 入口的 `export const inject = ['slots']` 声明，cordis 机制）。
4. **平台模块表以官方 dist seed 为准**：`shared/web-platform.ts` 更新为上列 9 项；`shared/tsdown.client.ts` 删除 `dsh-client-runtime/client` 的表外豁免——非表内 `@deepseek-ai/*` 值导入直接在纯度门构建失败（本插件 client 半区唯一的值导入是 react，不受影响）。
5. **openPath 降级为弹层兜底**：client 侧对 `workspaces?.openPath` 的结构探测保留（未来官方恢复能力时自动升回直达打开），0.1.5 上三处入口（人设文件/内置模型清单/自定义模型文件）统一走弹层（复制路径/模板）。

## Alternatives Considered

### 备选方案 A：插件自带「打开文件」Host 路由（仿官方 open-in-app）

- Pros：恢复一键直达打开。
- Cons：Host 侧拉起外部程序是新增攻击面，须自建 connection 信任栅栏等安全配套；属于新功能而非版本适配。
- Rejected：适配保持最小面；若官方后续提供公共 openPath 能力则自动恢复，否则作为独立需求另行评审。

### 备选方案 B：继续 pin 0.1.0-rc.6 并声明不兼容新版

- Cons：新版 DSH 上 `dsh-client-runtime` 已不存在，peer 解析与类型检查均失败，实际不可维持。
- Rejected。

## Consequences

- 插件可运行于 dsh 0.1.5-rc.1（本仓 typecheck/build/test 全绿）；0.1.0-rc.6 及更早版本不再受支持。
- 三个「↗」入口在新版 DSH 上点击后弹出「复制路径/模板」弹层而非直接打开文件（用户可感知的行为变化，spec §2 已同步）。
- 后续 DSH 升级时，先核对 `shared/web-platform.ts` 与 dist seed 表、`settings.section`/`shell.overlay` 声明、以及官方插件依赖模式三处即可快速定位破坏面。
