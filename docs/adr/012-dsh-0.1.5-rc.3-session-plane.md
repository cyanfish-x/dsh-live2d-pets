# ADR-012: 适配 DSH 0.1.5-rc.3 并接入会话面能力（直达打开恢复、交付庆祝）

## Status

Accepted

## Date

2026-09-24

## Context

DSH `latest` 频道推进到 0.1.5-rc.3（本机全局 dsh 同步升级验证）。以官方发布产物为本源逐项核实：

1. **rc.1 → rc.3 对本插件契约面零破坏**。官方 git tag `dsh-v0.1.5-rc.1...dsh-v0.1.5-rc.3` 的全部提交只涉及 message-feedback / deliverables / chat UI 与发布工程（vendor pin），未触碰本插件依赖的任何契约：`agent/*` 事件、`WebRoute`/`webServer.register`、settings namespace、`approval/request`、种子模块表（前端 dist 实测 9 项与 rc.1 完全一致）、cordis 4.0.2。`@deepseek-ai/dsh-settings` 官方停在 0.1.5-rc.1 未随行。devDeps 升 `^0.1.5-rc.3` 后本仓 typecheck/build/test 全绿。
2. **0.1.5 系列引入两个对桌宠有价值的会话面公共能力**（经用户确认接入）：
   - **`session/openWorkspacePath` Host Remote**（`dsh-api-session-controller`）：客户端远程面按 `remote.<namespace>` 安装命名空间服务（`dsh-api-gateway` client 的 `remoteServiceKey`，实测服务键 `remote.session`；`sessionController` 服务只在 Host 侧存在，客户端探测它恒为 undefined——首版实现即踩此坑）。请求 `{ path, action?: 'reveal' }`；Host 侧实现**不做工作区围栏**（任意绝对路径交给系统原生打开器），受 `nativeOpen` 部署策略与连接信任栅栏门控，另有 `canOpenWorkspacePath` 能力探测方法。ADR-011 时随 `IWorkspaces.openPath` 移除而丢失的「文件直达打开」在**新的会话面**上恢复；旧面（workspace controller）上的 openPath 实测仍未恢复。
   - `session/event` Cordis 总线（`dsh-session`）上的 `deliverables/presented` 会话事件（`dsh-tool-present` 声明合并进 `SessionEventMap`）：模型经 present 工具显式交付文件时触发，携带文件清单。
3. 同批调研核实但**本次未接入**：`feedback/committed` Context 事件（👍/👎 反馈情绪反应，用户未选）；官方 open-in-app webServer 路由（面向工作区目录 + 编辑器目录，与单文件直达场景重合度低）。

## Decision

1. **依赖矩阵跟进 rc.3**：`dsh-agent` / `dsh-host-webserver` / `dsh-user-approval` 升 `^0.1.5-rc.3`；`dsh-settings` 保持 `^0.1.5-rc.1`（该包官方最新）；新增 `dsh-session` / `dsh-tool-present` devDeps（`^0.1.5-rc.3`）——后者仅供 Host 侧事件类型（纯类型导入，运行时零模块表请求）。
2. **openPath 客户端探测链**（保持 ADR-011 decision 5 的探测哲学，三处 ↗ 入口统一生效）：
   1. `ctx.get('remote.session')?.openWorkspacePath({ path })`（0.1.5 客户端远程面，结构探测；Host 侧不做工作区围栏，任意绝对路径交给原生打开器，被 `nativeOpen` 策略拒绝或调用失败即落兜底）；
   2. 旧面 `ctx.get('workspaces')?.openPath(path)`（0.1.0 时代，官方恢复则自动升回）；
   3. 弹层兜底（复制路径/模板）。
3. **新增宠物状态 `delivered`（交付庆祝）**：Host 侧 `ctx.on('session/event')` 过滤 `event.type === 'deliverables/presented'` → 进入 `delivered`，保持 3.5s 后回 idle（与 done 同机制、同计时器字段）：
   - `delivered` 保持期内到达的 `agent/turn-stopping`（done）与 `agent/status` idle **不打断庆祝**——交付是比轮次结束更强的完成时刻，避免庆祝被紧随的轮次结束覆盖；
   - `thinking` / `error` / `waiting`（真实工作流事件）仍即时打断；
   - `done` 保持期内发生交付则升级为 `delivered`。
4. **动画槽位 9 → 10**（+`delivered`，默认候选链 `['Jumping', 'Done', 'Idle']`）；**台词池 13 → 14**（+`delivered`，六内置人设各配 2 句，自定义人设按既有 Partial 覆盖规则免迁移）。

## Alternatives Considered

### 备选方案 A：交付复用 done 状态（不加新态/槽位/台词池）

- Pros：改动面最小，零 schema 变化。
- Cons：无法区分「交付成果」与「普通轮次结束」，用户不能为交付单独配动作与人设台词；且 done 由 turn-stopping 触发，present 之后的 turn-stopping 会造成双庆祝或语义混叠。
- Rejected：用户明确选择接入交付庆祝语义。

### 备选方案 B：交付庆祝同时接入 feedback/committed（反馈情绪）

- Cons：用户本次未选；属独立可加需求，接口（Context 事件 + SessionInspection 尾事件解析 rating）已核实，随时可加。
- Deferred。

### 备选方案 C：不接 openWorkspacePath，维持弹层兜底

- Cons：官方已在会话面提供公共能力（含 connection 信任栅栏），三处 ↗ 入口体验差无理由维持。
- Rejected。

## Consequences

- 插件可运行于 dsh 0.1.5-rc.3；0.1.5-rc.1 上行为不变（sessionController 探测不到 → 回退旧链 → 弹层）。
- 三处 ↗ 入口（自定义人设 / 内置模型清单 / 自定义模型文件）在 0.1.5-rc.3 上恢复直达打开；`nativeOpen` 被部署策略关闭或调用失败时自动回退弹层（spec §2 已同步）。
- 新状态/槽位/台词池均为**加法**变更：自定义动画映射与自定义人设无需迁移（Partial 覆盖、缺省回退默认链）。
- 后续 DSH 升级时的核对清单新增两处：`sessionController` remote 面（openWorkspacePath 签名）、`session/event` 总线事件类型（deliverables/presented 载荷）。
